# Windows 安装目录启动入口设计

## 目标

Windows 安装完成后，除保留桌面上的 Codex 集成启动入口外，还要在实际安装目录 `Feature Kanban` 中提供两个可双击入口：

- `启动 Codex 与任务看板.lnk`
- `启动任务看板服务.lnk`

第二个入口面向不使用 Codex 的场景。它在可见控制台窗口内以前台进程启动 Feature Kanban 服务，确认监听成功后自动使用默认浏览器打开 `http://127.0.0.1:46171`。用户关闭该窗口或按 Ctrl+C 时，服务进程随窗口退出，不在后台残留。

安装器不再创建开始菜单快捷方式。更新安装时应清理旧版本创建的 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Feature Kanban\Codex.lnk`；卸载器继续识别并清理这个历史路径，以兼容旧安装。

## 选定方案

新增一个专用的独立服务入口程序，并让服务直接运行在该入口对应的 Node.js 前台进程中。入口程序复用现有服务应用构造逻辑，设置已安装版本固定使用的地址、端口、静态资源目录和数据目录规则，在监听成功后调用 Windows 默认 URL 处理器打开浏览器。

不使用后台服务子进程作为独立入口的主体。这样关闭可见窗口时，承载 HTTP 监听的就是被 Windows 终止的前台进程，不依赖父进程退出后再清理子进程，也不需要增加“停止服务”快捷方式。

安装目录中的 Codex 集成入口继续调用现有 launcher，与桌面快捷方式共用同一启动命令。现有 Codex 启动、服务健康检查、端口复用和 Codex 退出后停止自有服务的行为不变。

## 备选方案

仅添加 `.cmd` 或 `.ps1` 包装脚本的改动更小，但脚本若在后台启动 Node.js 后再等待健康检查，关闭脚本窗口不保证子进程同步退出；若以前台方式调用 Node.js，又难以在服务真正就绪后可靠地启动浏览器。该方案不满足“关窗即停服”的明确要求。

完全后台运行并新增“停止任务看板服务”入口可以显式管理生命周期，但会增加常驻进程和第三个入口，且与已确认的可见窗口交互不符。

## 安装和升级行为

安装器生成并记录以下快捷方式：

1. 现有桌面 Codex 集成快捷方式。
2. `<InstallRoot>\启动 Codex 与任务看板.lnk`。
3. `<InstallRoot>\启动任务看板服务.lnk`。

安装目录入口采用固定名称，每次安装或升级覆盖同一位置。安装清单记录这三个当前入口，卸载时按既有安全校验删除它们，然后删除安装目录。

开始菜单入口不再加入新安装清单，也不再创建。安装器在完成路径校验后删除精确的历史开始菜单快捷方式，并只在其父目录为空时移除该目录。卸载器保留历史路径白名单，并在卸载当前或历史清单时都检查这个精确路径，使升级未完成或旧版清单仍记录该入口时也能清理；不会删除开始菜单目录中的其他内容。

桌面快捷方式沿用当前名称选择规则，避免覆盖与 Feature Kanban 无关的 Codex 快捷方式。

## 独立服务控制流

`启动任务看板服务.lnk` 打开可见 PowerShell 窗口，并使用安装包自带的 `runtime\node.exe` 启动专用入口。PowerShell 只负责设置安装根目录和启动前台 Node.js，不把服务转为后台进程。

专用入口按以下顺序执行：

1. 从安装器提供的环境变量解析并校验安装根目录。
2. 清除外部传入的 host、port 和 data-dir 覆盖，固定使用已安装版本的 `127.0.0.1:46171` 及现有用户数据目录规则。
3. 配置安装目录中的静态资源和版本信息。
4. 在当前进程创建并启动 Feature Kanban HTTP 服务。
5. 监听成功后输出服务地址，并通过可替换、可测试的 Windows URL 打开适配器启动默认浏览器。
6. 收到 Ctrl+C、终止信号或 Windows 控制台关闭通知时关闭 HTTP 服务和数据库，再退出进程；若 Windows 在宽限期后强制结束控制台进程，服务监听仍随承载进程终止。

如果端口已被占用，入口沿用现有服务启动错误口径并返回非零状态，不尝试终止占用端口的进程。快捷方式承载的 PowerShell 在非零退出时停留并提示用户按 Enter 关闭，使错误不会一闪而过。浏览器只在本次服务成功监听后打开。

## 错误处理与安全边界

- 缺少或无效的安装根目录时，独立入口显示错误并非零退出。
- 浏览器启动失败不停止已经成功运行的服务；窗口显示警告，用户仍可手动访问输出的 URL。
- 端口冲突不会复用、接管或终止其他进程，避免“关闭本窗口”影响并非由本入口创建的服务。
- 独立入口不修改数据库格式、API、监听端口、数据位置或权限。
- 新增快捷方式仍使用 Windows `.lnk`，不依赖用户的 nvm 或系统 Node.js；运行时始终使用安装包自带的 Node.js。
- 自动化测试不创建真实桌面或开始菜单快捷方式，不启动真实浏览器，也不修改活动安装目录。

## 代码与测试范围

预计修改范围：

- `installer/install.ps1`：支持不同启动命令的快捷方式，创建两个安装目录入口，停止创建并清理历史开始菜单入口，更新清单内容。
- `installer/uninstall.ps1`：保留历史开始菜单路径兼容性，并允许当前安装目录入口通过清单安全清理。
- `src/server` 或相邻 launcher 目录：新增前台独立服务入口及可测试的浏览器打开适配器。
- Windows 包校验脚本：要求新编译入口存在。
- 安装器、launcher/server 和包清单测试：覆盖快捷方式集合、历史入口清理、前台生命周期、成功后打开浏览器、端口冲突和浏览器失败。
- 安装文档：说明两个安装目录入口、桌面入口以及开始菜单行为。

验证至少包括定向单元测试、Windows 安装器脚本测试、生产构建和 Windows 包暂存校验。由于 `npm run check` 最后会执行 `build:installer`，本次按用户要求不直接运行该聚合命令，而是依次运行其中除 `build:installer` 之外的 `typecheck`、`test`、`build`、`stage:windows` 和 `verify:package`，并确认现有 `FeatureKanbanSetup.exe` 未被修改。

## 验收标准

- 新安装的 `Feature Kanban` 目录中存在两个名称明确、可双击的 `.lnk` 入口。
- 桌面 Codex 集成快捷方式继续存在并保持原行为。
- 新安装不创建开始菜单快捷方式；升级会删除旧版的精确开始菜单入口。
- 独立服务窗口启动成功后自动打开默认浏览器。
- 关闭独立服务窗口或按 Ctrl+C 后，46171 端口不再由该入口启动的服务占用。
- 端口冲突时不打开浏览器、不终止其他进程，并保留可见错误。
- 卸载能兼容当前清单和仍记录旧开始菜单入口的历史清单。
- 所有入口使用打包运行时，不依赖用户的 nvm 环境。

## 变更面约束

本功能获准扩展 Windows 安装器的快捷方式清单、移除开始菜单入口，并新增独立服务的前台启动与停止流程。受保护的现有行为包括桌面快捷方式选择规则、Codex 集成 launcher、服务端口和健康检查、API、数据库、数据目录、Skill 安装与恢复、卸载身份和路径安全校验，均不得改变。

运行容量影响仅限用户主动打开独立服务入口时新增一个与现有服务等价的单实例前台进程；不新增后台常驻服务、轮询任务或并发监听。低侵入的包装脚本方案因无法可靠保证关窗停服而被拒绝。
