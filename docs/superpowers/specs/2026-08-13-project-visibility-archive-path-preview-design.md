# 项目可见性、归档与路径预览设计

## 目标

本次交付让本地单用户 Feature Kanban 可以持久隐藏项目及其卡片、临时查看全部隐藏项目，并从卡片详情打开原始项目目录和预览作为需求规格的 Stage 1 spec 文档。Feature Lifecycle 上报协议同时补充原始项目完整路径、产出 spec 路径，以及 Stage 4 的短批次描述。

当前 `master` 的 `2c28870` 已经让“已归档”以与进行中相同的六列卡片宽度展示全部归档卡片，并移除了错误的“已完成”分组。本次不重写该实现，只保护并回归验证这两个行为。

## 已确认的交互

项目导航中的每个项目都有独立的隐藏或恢复操作。隐藏标记保存在 SQLite，不依赖具体浏览器；刷新、重启应用或换一个浏览器打开本地看板后仍然有效。

默认关闭的眼睛按钮位于“项目”和 `All` 之间。关闭时，SQLite 中标记为隐藏的项目入口及其当前视图卡片都不显示；打开时，所有隐藏项目及其卡片临时出现，项目入口带隐藏状态标识，并可单独恢复。眼睛按钮只是当前页面的临时查看开关，不修改 SQLite。隐藏当前选中的项目时，页面先回到 `All`，避免留下一个不可见筛选条件。

项目隐藏按现有项目身份 `projectName` 生效。不同绝对路径但同名的仓库仍按现有约定聚合成同一项目，并共享隐藏状态；本需求不改变项目身份模型。

详情抽屉新增原始项目完整路径。存在路径时可通过明确的“打开项目”按钮在 Windows Explorer 或 macOS Finder 中打开；旧卡片没有路径时显示不可用，不推导或猜测路径。

生命周期文档继续显示路径并支持复制，但不提供预览。详情新增“需求文档”：它固定指向本次 Stage 1 产出并提交的 spec，点击后在抽屉中打开页面内 Markdown 预览。预览支持需求规格常见的标题、段落、列表、任务列表、引用、分隔线和代码块；嵌入 HTML 作为文本处理，不执行脚本。用户可以返回详情或复制 spec 路径。外部需求来源不作为该入口的预览目标。

卡片左上角显示项目名，右上角继续显示同步时间。原来位于左上角的 AI 工具标识以及标题下方重复的项目名从卡片移除；AI 工具保留在详情抽屉中显示，工具筛选行为不变。

卡片跨阶段时保留现有“抬起—滑行—落位”语义，但把当前 480ms 的快速移动延长为约 900ms，并调整关键帧使抬起、主体滑行和落位各自可辨，形成更有仪式感的一次完整迁移。动画仍不显示文字提示；系统启用减少动态效果时继续完全跳过位移动画。

## 方案选择

采用“SQLite 项目偏好 + 卡片路径元数据 + 卡片作用域本地操作 API”。`project_preferences` 只存每个 `projectName` 的隐藏标记；卡片继续存自己的生命周期文档路径，并新增可空的原始项目路径与产出 spec 路径。UI 通过项目 API 改变持久隐藏状态，眼睛开关只改变当前视图投影。

未采用浏览器 `localStorage`，因为隐藏项目会改变业务视图，而本产品已经是单用户本地服务；SQLite 能让不同浏览器和应用重启保持一致。也未采用完整的项目配置表或把隐藏标记复制到每张卡片，这两种方案会引入无必要的身份迁移和重复数据。不能从 `lifecycleDocumentPath` 推导项目根目录，因为生命周期文档位于 linked worktree 时会得到错误路径。

## 数据和 API

SQLite 新增可空的 `cards.project_path` 和 `cards.spec_document_path`。新数据库直接包含这两列；已有数据库在启动时执行幂等迁移，旧行保持 `NULL`。新增 `project_preferences(project_name PRIMARY KEY, hidden)`，不移动、不重写卡片或会话数据，也不把 Markdown 内容复制进数据库。

`POST /api/cards` 接受可选 `projectPath`。服务端只接受绝对路径并按原样保存；发布后的 Feature Lifecycle Skill 必须上传启动流程时保存的原始 `<repo-root>` 完整路径。字段在 API 中保持可选，以免旧版 Skill 立即失效。相同 `cardId` 的幂等重试若既有路径和新路径都存在但不同，返回 `409`；既有旧卡片没有路径时仍按原有身份字段返回，不隐式猜测或覆盖。

完整快照更新接受可选 `specDocumentPath`；创建卡片时 Stage 1 尚未产出 spec，因此不要求该字段。Stage 1 生成并提交 spec 后，Skill 第一次上传该绝对路径，并在此后每次完整快照都携带。该字段是可更新元数据，旧 Skill 省略时保留既有值。开发期间路径指向 feature worktree；base 成功整合后、上报 `completed` 前，Skill 将其切换为 `<repo-root>` 下相同相对路径，保证 worktree 清理后路径仍然有效。

`ProjectSummary` 新增 `hidden`。`PATCH /api/projects/{projectName}/visibility` 只接受 `{ "hidden": boolean }`，项目不存在时返回 `404`；成功后发布项目变更事件，使打开的页面执行一致性刷新。`GET /api/cards` 不隐式排除隐藏项目，避免改变现有调用方和筛选协议；页面按 `ProjectSummary.hidden` 与眼睛开关投影卡片。

`POST /api/cards/{cardId}/open-project` 不接收文件系统路径。它只读取该卡片已存 `project_path`，确认其为现有目录后调用当前平台的文件管理器；缺少路径、目录不存在或平台不支持时返回明确错误。

`GET /api/cards/{cardId}/spec-document` 同样不接收路径，只读取卡片已存 `spec_document_path`。服务端要求文件存在、是普通 Markdown 文件且不超过 1 MiB，再返回 UTF-8 内容和路径。文件读取失败不会关闭详情抽屉，也不会回退读取生命周期文档或外部需求来源。

Stage 4 的 `LifecycleProgress` 新增可选 `implementationSummary`。存在时去除首尾空白后必须为 1–10 个 Unicode 字符，且不能只匹配“批次1”或 `batch 1` 这类序号。字段在服务端保持可选以兼容旧 Skill；随产品发布的 Skill 则要求每次 Stage 4 完整快照都携带能说明当前批次内容的短描述，例如“项目隐藏”或“路径预览”。卡片优先显示该描述，并保留批次号、评审轮次和连续干净轮数。

## 组件与数据流

服务端仓储负责卡片路径迁移、spec 路径更新、项目偏好读写及项目汇总。路由只把经过校验的卡片 ID 或项目名交给仓储；本地文件服务封装目录打开和受限 spec Markdown 读取，平台进程启动可注入替身以便测试。

页面 Store 保存从服务端取得的项目隐藏标记和当前眼睛开关。项目隐藏/恢复成功后刷新项目与卡片投影；SSE 项目变更触发全量刷新。Board 页面只渲染当前眼睛状态允许的项目和卡片，并使 All 数量、项目数量及状态行数量与实际可见内容一致。

详情组件通过卡片 API 请求打开目录或读取 spec。Markdown 预览组件把文本解析成受控的展示块，不绑定未经处理的 HTML，也不向服务端传任意路径；界面将该 spec 标注为“需求文档”。

## 错误与兼容性

旧数据库自动增加列和偏好表，不删除数据。旧卡片详情仍可复制生命周期文档路径，但没有项目路径时不能打开项目，没有 spec 路径时不能预览需求。旧 Skill 没有 `projectPath`、`specDocumentPath` 或 `implementationSummary` 时 API 继续接受；新 Skill 的文档和测试保证新流程在相应阶段上传它们。

项目隐藏写入失败时保持当前服务端状态并显示现有看板错误提示。打开项目或预览失败只在详情区域显示操作错误。路径接口不接受查询参数或请求体路径，从而不把回环 API 变成任意文件读取或任意路径启动接口。

## 变更面契约

交付目标涉及 `skills/feature-lifecycle` 的调用协议、`src/shared` 的卡片/项目/进度契约、`src/server` 的 SQLite schema、仓储、路由和本地文件操作，以及 `web/src/app` 的 Store、项目导航、详情和 spec Markdown 预览。

预计新增：项目偏好持久化表；项目隐藏 API；卡片作用域的打开目录和读取 spec API；安全 Markdown 预览组件；相应服务端、UI 与 Skill 合同测试。

预计修改：卡片创建校验和持久化增加可空 `projectPath`，卡片快照增加可更新的 `specDocumentPath`；项目汇总增加 `hidden`；SSE 事件支持项目变更；Stage 4 进度增加短描述；Board 导航和可见卡片投影增加隐藏状态；卡片左上角改为项目名并把 AI 工具收敛到详情；卡片跨阶段动画延长到约 900ms 并明确三段节奏；详情保留生命周期文档复制并增加项目路径操作与需求预览入口；Skill 主文档、生命周期模板与 API reference 要求上传原始项目完整路径、产出 spec 路径及语义批次描述，并在最终整合时重写 spec 路径。

预计删除：无生产模块、字段、路由或既有行为。

受保护行为：卡片仍由 `cardId` 标识；项目仍按 `projectName` 聚合；AI 工具筛选仍按 `aiTool` 生效且详情继续显示该值；完整 PATCH 仍是最后写入者覆盖并自动取消归档；归档不改变生命周期；已归档视图继续显示所有阶段且保持六列卡片宽度；进行中视图继续排除初始化和已完成投影；阶段变化仍只播放一次迁移动画且减少动态效果时跳过；看板仍不能修改生命周期阶段；服务仍只监听回环地址并保持现有 Origin 限制；任何路径操作都不写文件。

持久化和公共 API、目录打开、spec 文件读取属于已向用户披露并明确批准的变更面。低侵入保真策略是让新字段在 API/数据库中可空、仅由新版 Skill 强制上报，且所有文件系统操作只使用卡片已存路径。代价是旧卡片没有“打开项目”或需求预览能力，旧 Skill 的 Stage 4 卡片没有语义批次描述。

资源影响限于每项目一行偏好、每卡片两个可空路径和用户点击时最多读取 1 MiB 文件；数据库不保存 Markdown 内容。目录打开不常驻子进程，spec 文档不监听文件变化。本次不执行大数据量、跨平台真实 Explorer/Finder 或安装后 GUI 压测，这些是未验证项。

## 验证

生产实现完成后补最小行为测试，不为测试改变生产接口。服务端测试覆盖旧数据库迁移、项目/spec 路径字段兼容和更新、项目隐藏持久化、项目事件、非法路径、缺失目录、spec Markdown 类型和大小限制。UI 测试覆盖单项目隐藏/恢复、眼睛开关、当前选择回退、卡片与计数一致性、卡片项目名/详情 AI 工具分工、约 900ms 三段迁移动画和减少动态效果、生命周期文档仅复制、需求预览操作错误及安全 Markdown 展示。Skill 测试覆盖 `projectPath`、`specDocumentPath` 的 Stage 1 上报与整合路径切换、生命周期文档中的项目完整路径、Stage 4 `implementationSummary` 的十字限制和禁止无语义批次文本。

现有归档专项测试继续证明全部归档阶段、无“已完成”分组以及六列卡片宽度。最终运行项目完整质量门禁 `npm run check`。
