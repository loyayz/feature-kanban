# 看板创建 Codex 任务设计

## 目标与范围

本次做一个可实际运行的最小验证：用户在看板右上角点击“创建任务”，输入第一条提示词并确认后，Feature Kanban 服务端在当前选中的具体项目目录中创建一个新的 Codex 对话，并立即启动首个 turn。创建成功后，弹窗内显示“打开 Codex 对话”，点击后复用现有宿主导航能力打开该对话。卡片详情也补充明确的“打开 Codex 对话”入口，仅在卡片已有真实 Codex 外部会话 ID 时可用。

任务创建不新增卡片、不把新对话自动关联到卡片，也不持久化弹窗内的 thread ID；关闭弹窗后本次快速入口消失，但任务仍保留在 Codex 中。用户已明确接受该最小验证边界。

## 已确认交互

“创建任务”位于活动看板工具栏右侧。当前项目为“All”时按钮禁用，并提示先选择一个具体项目；当前工具筛选不影响任务的 Codex 类型。点击按钮打开模态弹窗，弹窗包含一个最多 4000 个字符的多行输入框、取消和确定按钮。空白提示词不能提交。

提交期间输入框和操作按钮进入忙碌状态，避免重复请求。服务端在 `thread/start` 和 `turn/start` 均成功后返回真实 thread ID；弹窗保留输入内容并显示成功状态与“打开 Codex 对话”按钮。失败时弹窗保持打开并展示可操作错误，用户可以修改提示词重试。打开动作调用现有 `CodexHostService.openCodexSession()`，不增加第二套导航协议。

卡片详情在会话区域上方展示一个明确的“打开 Codex 对话”按钮，目标为该卡片最新一条具有非空 `externalSessionId` 的 Codex 会话；没有真实 ID 时显示禁用按钮和“暂无可打开的 Codex 对话”说明。既有逐会话操作保留，但 Codex 会话的按钮文案统一为“打开 Codex 对话”，避免把仅有本地生命周期记录的会话误认为可跳转。

## 服务端与数据流

新增 `POST /api/codex/tasks`，请求体为 `{ "projectName": string, "prompt": string }`，成功返回 HTTP 202 和 `{ "threadId": string, "status": "in_progress" }`。接口复用当前 loopback HTTP 服务及现有 Origin 防护，不增加 token、登录或远程访问能力。用户已明确授权本次新增 loopback 公共 API、启动 Codex 外部子进程，以及维持“仅回环、无 token”的现有安全模型；这意味着同一用户下的其他本地进程也能触发 Codex 任务，属于本次已接受风险。

客户端不传文件路径。仓储根据 `projectName` 查询现有卡片记录中的非空 `project_path`，去重后必须恰好得到一个路径；没有路径或同名项目对应多个路径时拒绝创建并返回可读错误。路径还必须是现存目录。由此避免浏览器任意指定 Codex 工作目录，同时诚实处理当前按项目名聚合可能合并同名目录的数据模型。

服务端持有一个进程内全局任务占用标记，同时最多允许一个由看板创建且仍在执行的 Codex turn。占用时新请求返回 409；进程启动、协议初始化、`thread/start` 或 `turn/start` 失败时释放占用并终止子进程。成功响应后服务端继续读取通知，直到收到对应 `turn/completed`、子进程退出或协议流关闭，再释放占用。服务重启不会恢复占用状态，也不影响已经由 Codex 接管的任务。

## Codex App Server 接入

新增可注入的 `CodexTaskRunner` 边界和默认 `CodexAppServerTaskRunner`。默认实现优先使用 `FEATURE_KANBAN_CODEX_PATH` 指定的绝对可执行文件路径，否则从服务进程的 PATH 启动 `codex app-server`，通过标准输入输出交换每行一个 JSON 的 JSON-RPC 消息。启动顺序为：发送 `initialize`，接收成功响应，发送 `initialized` 通知，发送 `thread/start`（`cwd` 为已解析项目目录），取得 `thread.id`，发送 `turn/start`（`threadId` 与用户提示词），确认返回 turn 后向 HTTP 层报告成功并后台跟踪完成通知。

请求不覆盖模型、推理强度、审批策略或 sandbox，全部沿用用户现有 Codex 配置。JSON-RPC 响应按请求 ID 关联；协议错误、结构缺失、stderr 诊断和意外退出被归一化为不泄露提示词或环境细节的服务错误。HTTP 响应只返回 thread ID 与状态，不返回原始协议帧。子进程完成后关闭输入并终止残留进程，监听器必须清理。

本次最小验证不把 Codex CLI 或 Node.js 加入项目依赖或安装包，也不读取 Codex 桌面的私有资源目录。Windows/macOS 启动器使用本机 Node.js 24+；`FEATURE_KANBAN_NODE_PATH` 可显式指定，否则使用启动环境中的 Node。服务进程使用 `FEATURE_KANBAN_CODEX_PATH` 或 PATH 中的 `codex`。本机运行时缺失或版本不满足时返回明确错误。是否随安装包分发任何运行时留到验证成立后另行决策。

## 错误映射与资源限制

请求体错误、空白提示词、超过 4000 字符或无效项目名返回 400；项目不存在、没有唯一目录或目录失效返回 409；已有任务执行中返回 409；Codex 运行时缺失或无法启动返回 503；App Server 初始化或启动 turn 失败返回 502。前端优先显示服务端稳定错误文本，网络错误使用统一兜底文案。

每次请求至多启动一个子进程；stdout 按行增量解析并限制未完成单行缓冲区，stderr 只保留有限诊断长度。首个 turn 启动设置有限超时，任务执行本身不设短超时，由 Codex 完成事件或进程生命周期回收。接口不记录完整提示词，不新增数据库表、迁移或日志字段。

## 测试与验收

服务端测试使用假的任务运行器覆盖：合法请求解析唯一项目目录并返回 202、提示词边界、All/未知/歧义/失效目录、忙碌冲突、运行时和协议错误映射。App Server 单元测试使用假的子进程流验证初始化顺序、`thread/start` 的 cwd、`turn/start` 的提示词、响应关联、完成后释放、异常退出与缓冲限制。

Web 测试覆盖：具体项目时按钮可用、All 时禁用；弹窗打开、空白校验、提交忙碌态、成功后打开真实 thread ID、失败可重试；卡片详情从最新有效 Codex 会话打开，缺少外部 ID 时明确禁用，非 Codex 会话不被选作主入口。最终运行完整 `npm run check`，并在可用的本机 Codex 命令与登录配置下手工验证创建后立即执行与宿主跳转。

## 变更面契约

预计新增服务端任务协议、App Server runner 与对应测试；修改 `src/server/app.ts`、`src/server/routes.ts`、卡片仓储接口和实现以接入 API 与唯一项目路径解析。Web 侧修改看板页面、API service、共享模型以及卡片详情组件和测试。按用户追加要求，Windows/macOS staging、启动器、安装脚本和包校验改为依赖本机 Node.js，不再复制 Node 可执行文件；项目依赖和安装包均不携带 Codex CLI。

受保护行为包括现有卡片 CRUD、阶段迁移、归档、SSE、项目隐藏、目录/spec 资源接口、现有 Codex 会话导航、注入脚本与宿主路由协议、数据库表结构和生命周期状态机。新增接口只接受项目名与提示词，绝不接受客户端路径；现有 loopback/Origin 安全边界不放宽到非回环地址。当前任务必须已经进入 Codex 后才显示打开按钮，不生成伪造会话 ID。

本次明确触发并已获得授权的变更面为：新增 loopback 公共 API；启动并管理用户环境中已有的官方 Codex 外部进程；移除 Windows/macOS 安装包内既有的 Node.js 副本并改用本机 Node.js；接受无 token 的本地调用风险。未授权且不在范围内的变更包括随安装包分发 Codex 或 Node 运行时、读取 Codex 桌面的私有二进制路径、远程 API、身份认证、任意路径执行、多任务并发、任务取消、历史记录持久化、自动建卡或自动关联卡片、改变 Codex 用户配置和调整数据库事务边界。
